# DiLoCo Arithmetic Contract

This package is a pure numerical foundation, not an enabled distributed
training runtime. It imports only the Go standard library and receives no
leases, credentials, provider records, or private inner-optimizer state.

Given float32 base parameters and local parameters, `Delta` computes
`base - local`. `Step` accepts exactly one contribution from every worker in
the committed cohort, with exactly H attempts, H commits, zero skips, and
positive effective-token counts. Uniform aggregation weights each worker
equally; effective-token aggregation divides by the sum of accepted counts.

The update is:

```text
g = weighted_mean(delta)
m_next = beta * m + g
theta_next = theta - lr * (g + beta * m_next)
```

There is no outer weight decay. The caller retains private AdamW moments;
they never enter this calculation.

## Ordering And Precision

- Tensor order is the program/checkpoint weight-layout order, including exact
  names and shapes. Adapters must not use map or safetensors header order.
- Workers reduce in the caller's committed cohort order, not arrival order or
  lexical ID order. Counts sum exactly in uint64, with overflow rejection.
- Weights and reductions use float64. Normalize each weight before summing;
  round the completed aggregate once to float32. Compute momentum in float64
  from that aggregate and old float32 momentum, then round to float32. Compute
  the final Nesterov expression in float64 using the rounded new momentum,
  then round model parameters to float32.
- Explicit float64 conversions separate multiply/add operations and prohibit
  compiler fusion across these boundaries, including cancellation between
  large opposing worker contributions.
- Delta subtraction uses float64 intermediates and rounds to float32. Reject
  non-finite values and out-of-range state results. Return fresh arrays only
  after the whole operation succeeds; caller state is never mutated.
- Fixtures use absolute tolerance `1e-6` plus relative tolerance `1e-6`.
  Reordering arrival with a fixed cohort order must produce identical results.

## Oracle Provenance

`testdata/quadratics.json` is hand-computable, not generated by `Step`. Starting
at theta=4, workers minimize `0.5*(theta-target)^2` for targets 0 and 2 using two
local SGD steps of size 0.25. Thus local theta is
`target + (theta-target)*0.75^2`. The fixture locks three rounds of uniform,
token-weighted (1:3), and Nesterov (beta=0.5) results. SGD is used only to make
the outer oracle independent and auditable; it does not change the planned
AdamW learner contract.
